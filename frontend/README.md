# LexiGuard Frontend

A private, local-first document triage interface for rental and leave-and-licence agreements, built in **React + Vite + TypeScript**.

LexiGuard helps non-lawyers understand what readable agreements state with verbatim source evidence, highlights potential conflicts and ambiguities in attention-first order, and assists in preparing neutral questions for qualified legal professionals.

---

## Architecture & Design Principles

1. **Local-First & Private**:
   - Zero external network requests (no CDNs, remote Google fonts, external icons, telemetry, or analytics).
   - Zero persistent browser storage (`localStorage`, `sessionStorage`, `indexedDB`, and cookies are never used).
   - All document text, answers, questions, and evidence exist only in JavaScript application memory.
   - On document deletion, all associated state is completely purged from memory.

2. **One-Time Session Bootstrap**:
   - The launcher provides a one-time launch code via URL fragment: `http://localhost:8000/#k=<one-time-code>`.
   - The code is read once on startup and immediately stripped from the address bar via `history.replaceState`.
   - The code is exchanged via `POST /api/session` for an in-memory Bearer token.
   - On browser refresh or 401, the session is invalidated and requires reopening the launcher.

3. **Strict Evidence Gating & No Legal Verdicts**:
   - Answers and review cards only display source citations when verbatim quotes exist.
   - Missing clauses are presented truthfully as *"Not located in document"* (never as legal absence).
   - `legal_verdict` is always `null` by design. LexiGuard provides factual document triage, not legal advice or judicial predictions.

4. **Attention-First Risk Review**:
   - Review topics are prioritized to present potential clause conflicts first (with dual citations), followed by monetary/term ambiguities, penalties, and jurisdiction notices.

## Development & Testing Commands

All commands should be executed from within the `frontend/` directory:

```bash
# Install dependencies
npm install

# Start local Vite development server
npm run dev

# Run full test suite (Vitest)
npm run test

# Run Oxlint linter
npm run lint

# Compile TypeScript and build production bundle
npm run build

# Preview production build locally
npm run preview
```

## Live Backend vs. Mock Mode

- **Mock Mode**: Active by default in development (`npm run dev`) when no `#k=` launch code is present. Uses synthetic in-memory fixtures covering valid answers, conflicts, notice periods, OCR limitations, and legal boundaries.
- **Live Mode**: Automatically engaged when the frontend is loaded with `#k=<one-time-code>` generated by the FastAPI backend, or toggled via the dev toolbar button. Proxies `/api/*` requests to `http://127.0.0.1:8000` preserving the origin for host validation.
